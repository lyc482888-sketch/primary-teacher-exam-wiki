# AI Agents 是什麼？
### 從「會聊天的 AI」到「能辦事的智慧助理」
- 主講 / 整理：LLM Wiki 知識庫首席助教
- 目標對象：完全沒有程式背景的零基礎學習者
- 核心焦點：Agent 五大超能力、自主思考循環（Loop）、ReAct 框架、MCP 工具調用與未來教育

---

## 一、 傳統 Chatbot vs AI Agent 根本差異

| 比較向度 | 傳統對話機器人（Chatbot） | 智慧代理人（AI Agent） |
| :--- | :--- | :--- |
| **生動比喻** | 圖書館管理員（你問才答，只說不做） | **超級個人秘書**（交代目標，自動辦妥） |
| **互動模式** | 單次回合（Single-turn），被動等待指令 | **自主循環（Multi-turn Loop）**，主動推進 |
| **工具操作** | ❌ 沒有工具權限（無法查即時股票、不能寫檔） | ✅ **具備工具調用**（能上網、跑代碼、寫入檔案） |
| **出錯自省** | ❌ 產生自信的幻覺，直到被人類糾正 | ✅ **具備自我反省（Reflexion）**，報錯換招重試 |
| **任務規模** | 回答一題數學、翻譯一段文字 | 獨立建立包含 74 篇筆記的完整網站並發布雲端 |

## 二、 AI Agent 的五大超能力結構

1. **認知大腦（Brain / Planning）**：
   - 由強大的大型語言模型（LLM）擔任，負責意圖解析、目標拆解與決策。
2. **感官知覺（Perception）**：
   - 接收使用者指示、觀察螢幕、解析外部回傳之即時數據與報錯日誌。
3. **執行工具（Action / Tools）**：
   - 操作世界的雙手：檔案讀寫器、終端機命令、網頁瀏覽器、API 連接器。
4. **記憶系統（Memory）**：
   - 短期對話上下文 ＋ 長期外部記憶庫（LLM Wiki / 向量資料庫）。
5. **自我反省（Reflexion）**：
   - 執行後自動驗證成果，發現錯誤立即修正策略。

---

## 三、 自主思考循環（Loop & Graph）

AI Agent 的生命週期是由一個持續旋轉的閉環驅動：

```text
[感知環境 (Perceive)] 
       ➔ [制定計畫 (Plan & Think)] 
       ➔ [採取行動 (Act & Tool Call)] 
       ➔ [檢查反思 (Reflect & Observe)] 
       ➔ (達成目標？若未達成則持續 Loop)
```

- **終止條件**：所有子目標達成並通過驗證，或達到最大安全迭代次數。

---

## 四、 邊想邊做：經典 ReAct 思考框架

Yao 等人 (2022) 提出，將「推理（Reasoning）」與「行動（Acting）」無縫交織：

- **Thought 1**：分析目標，發現缺少某項關鍵數據。
- **Action 1**：呼叫工具檢索外部即時資料。
- **Observation 1**：讀取工具返回的真實數值。
- **Thought 2**：根據真實數據進行推論與驗證。
- **Action 2**：產出最終成果或進行下一步操作。
- **優勢**：大幅降低模型幻覺，答案具備 100% 事實可溯源性。

---

## 五、 工具調用（Tool Calling）與 MCP 開源協議

- **工具調用原理**：
  1. 向模型註冊工具說明書（JSON Schema）。
  2. 模型在需要時輸出函數調用格式（如：`read_file`）。
  3. 電腦系統真實執行該動作。
  4. 將真實結果（Observation）餵回給模型繼續推論。
- **MCP（Model Context Protocol）**：
  - Anthropic 於 2024 年提出之開源通用標準，被譽為「AI 時代的 Type-C」插槽，讓任何 Agent 都能跨平台隨插即用各種資料庫與工具。

## 六、 記憶體系：為什麼我們需要「LLM Wiki」？

- **對話框的極限**：
  - 聊天視窗會面臨上下文長度（Token Limit）膨脹，聊得越久，模型越容易遺忘早期細節。
- **Karpathy LLM Wiki 模式的突破**：
  - **知識資產化**：每次對話探討的精華，都落盤為持久的 Markdown 檔案。
  - **神經網絡化**：透過雙向連結 `[[ ]]` 與標籤，將分散的知識交織成網。
  - **滾雪球效應**：隨時間推移，知識庫越來越豐滿，成為個人的永久智慧資產。

---

## 七、 團隊力量大：多代理人協作（Multi-Agent Systems）

- **為什麼要分工？**
  - 避免單一 Agent 認知負荷過載、避免既當寫手又當裁判的盲點。
- **經典分工架構**：
  - **協調者（Coordinator）**：總攬全局，拆解指派任務。
  - **研究員（Researcher Agent）**：深挖原始講義，萃取實體。
  - **審查員（Reviewer Agent）**：把關排版、格式與邏輯。
  - **蜂群模式（Swarm）**：派出數十個輕量 Worker 同時平行處理任務。

---

## 八、 AI Agent 如何賦能教育與學習現場？

1. **蘇格拉底式自適應家教**：
   - 不直接給答案，而是透過步步提問（鷹架 Scaffolding）引導學生獨立開悟。
2. **終身知識庫管家（LLM Wiki Keeper）**：
   - 主動幫學生梳理數百頁雜亂講義，建立互動圖譜與自測題庫。
3. **自動化教材與簡報產製**：
   - 依據認證過的 Wiki 知識庫，一鍵端到端生成結構清晰、零破圖的教學簡報。

## 九、 結語：成為懂得駕馭 AI Agent 的超級個體

- **人類的核心價值**：定義真正重要的問題、確立價值觀與最終審查。
- **Agent 的核心價值**：承擔所有高強度、多步驟的繁瑣執行工作流。
- **未來公式**：
  $$\text{超級個體} = \text{清晰的思維目標} + \text{熟練駕馭的 AI Agent 團隊} + \text{持續積累的 LLM Wiki 知識庫}$$
